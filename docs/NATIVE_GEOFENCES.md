# Phase 14B.1: Windows native geofence sessions

Phase 14B.2 now provides a **separate explicit device-local background run**; see [BACKGROUND_GEOFENCES.md](BACKGROUND_GEOFENCES.md). The page-active behavior described below is unchanged. Current packages additionally declare the background bridge/COM server, and foreground native sessions cannot register while a background run reserves ownership. Neither mode is enabled merely by opening the app.

This increment adds **opt-in, page-active native sessions for packaged Windows**. The normal unpackaged app, mobile builds and Debug workspace preview show an unavailable explanation and retain Phase 14A manual checks. There is no closed-app activation, OS background task, background permission request, startup restoration or automatic registration/rearm. Phase 14B remains open.

Microsoft's WinUI geofencing guidance uses package identity and a location manifest capability, requests access on the foreground UI thread, and distinguishes running-app event handlers from background activation. See [Windows geofencing](https://learn.microsoft.com/en-us/windows/apps/develop/maps-and-location/geofencing) and [geofence setup/access](https://learn.microsoft.com/en-us/windows/uwp/maps-and-location/set-up-a-geofence). This project now declares the package's location capability; its default WindowsPackageType remains None.

## Build and use

1. The existing `scripts/Run-Windows.ps1` still starts the unpackaged app. Under Tools > Location reminders, native Start is disabled and the capability text explains why. Manual checks work as before.
2. `scripts/Build-WindowsPackage.ps1` builds an **unsigned Debug test MSIX/bundle**, using the repository SDK when present. Build and package artifacts go under ignored `.tools/windows-msix`, with package delivery under its `packages` folder. It does not create/trust a certificate, sign, install or launch anything. This is an optional development build, not a release distribution.
3. To run as packaged, configure a real package publisher/signing identity and install/deploy through the normal Windows/Visual Studio development workflow. Copying or directly running a packaged output executable does not grant package identity. Signing/trust and deployment are separate acceptance steps; see [MAUI Windows package publishing](https://learn.microsoft.com/en-us/dotnet/maui/windows/deployment/publish-cli?view=net-maui-10.0). The generated unsigned package is not installation acceptance.
4. Packaged app data/OS credential context can differ from the unpackaged installation. Create disposable test tasks/places in that installation. Do not copy/reset an existing encrypted location database without its original protected key.
5. In the installed packaged app, open Location reminders, select a workspace and Refresh. Arm 1-10 places; disable extra places before starting. Allow/check notifications first. Start native session asks for contextual confirmation and may prompt for Windows location access.
6. Start registers bounded OS regions and reads one foreground bootstrap fix. Only a reliable outside fix captured at/after session start can establish new outside evidence. Starting inside never alerts, even if the saved arm had outside evidence from an earlier check/session. Later native exit/entry reports can advance that same arm.
7. Stop native session cancels callbacks immediately and unregisters regions. Leaving/deactivating/stopping the page/window, switching workspace/account, canceling work, expiry, changed tasks/arms, native removal/unavailability or the first arrival check also ends the session. Reactivating the window never automatically restarts it. A permission dialog can interrupt Start; after granting access, explicitly retry.

## Native regions and delivery

WindowsGeofencePlatform registers **two regions per place**, with opaque random IDs, a ten-second dwell and thirty-minute native lifetime. Entry uses half the saved radius; exit uses saved radius + min(500 m, radius / 2) + 50 m. These deliberately conservative regions leave room for the accuracy/freshness checks shared with manual reminders. A 200 m place therefore uses a 100 m entry region and a 350 m exit region. Native arrival can require moving further inward than a manual check would. Events and delivery can be delayed or absent; these are not precise navigation boundaries.

Reports are ordered by fix timestamp, restricted to their exact registered reminder/arm and sent through LocationReminderService's normal task, accuracy, revision and notification checks. Unknown/stale session IDs, old arms, samples before Start, simulated/stale/inaccurate fixes and unconfirmed boundaries cannot consume an arm. Reliable outside evidence is also kept in the encrypted reminder state, but a new native session always requires new outside evidence in memory. One arrival check ends the whole session; other saved arms remain available for a later explicit Start.

Attempted is committed before generic OS notification delivery. Failure/crash can lose an alert; it cannot automatically repeat that arm. If notification access disappears mid-event, an arm may remain unconsumed while the native session ends. Refresh saved status before restarting/rearming. Native delivery and SQLite changes are not atomic; existing best-effort cancellation/race limits still apply. No task is completed, no provider/calendar data changes, and no location is uploaded to the Todo API.

## Ownership, cleanup and privacy

GeofenceSessionService is shared across app windows and reserves one page owner. Other windows cannot replace/stop its active session. Authorization is captured before waiting for its serialization gate. Account changes and page cancellation invalidate callbacks immediately, including when permission/native registration is still pending. A fifteen-second active-page reconciliation reads local task/reminder metadata and checks notification access; it never polls GPS. Changed task/occurrence/conflict or replaced/disabled arms stop the session. Every report also validates the registered cohort before processing.

The Windows adapter holds an exclusive file lease while managing this feature's native namespace, preventing another process from deleting its active registrations. It removes only IDs prefixed `todo-native-v1-`, never all package regions indiscriminately. Start acquires the lease after contextual access, removes leftover feature regions, drains old reports and creates new identities. Stop unsubscribes handlers before removing regions. If cleanup fails, callbacks remain blocked, the lease is retained for retry, and the page offers Stop / retry cleanup. Local reminder disable/delete is saved before that cleanup attempt.

Native session opt-in is **not persisted**. A crash/process termination releases the file lease but can leave OS-managed regions until their thirty-minute expiry or the next explicit Start cleans them up. No background handler is registered to show alerts from those orphaned regions. This is bounded cleanup, not a guarantee of immediate removal after a crash.

Saved application places remain encrypted in location.db3 schema 1 with the original SecureStorage key. Registration necessarily passes center/radius to Windows location services, outside that application encryption envelope; the Start explanation discloses this. OS/provider handling follows Windows location privacy/settings. No report sample, travel history or native registration journal is saved in SQLite. OS/package privacy and crash cleanup still require device testing. Native IDs contain no titles, place names, account scope or coordinates; notifications remain generic.
