# Android quick capture: launcher, sharing and widget

Implemented on 2026-11-14 after the user selected Android quick capture ahead of Apple tooling. Phase 14B.4 and earlier device/provider acceptance remain pending. Phase 15A is the launcher surface, Phase 15B adds plain-text sharing and Phase 15C adds a home-screen capture widget. Windows hotkeys and browser extensions remain future work.

## Try it yourself

1. Build the standalone debug APK with `powershell -ExecutionPolicy Bypass -File scripts/Build-Android.ps1`. The existing Android workload, SDK and JDK are required; see [ANDROID_GEOFENCES.md](ANDROID_GEOFENCES.md) for setup. This command builds only; it does not install or launch anything.
2. Install `.tools/android-build/bin/TodoApp.Maui/debug_net10.0-android/com.companyname.todoapp.maui-Signed.apk` on your test phone using your chosen Android tooling.
3. On Android 7.1/API 25 or later, long-press the app icon in a launcher that supports app shortcuts, then choose **Add task**. Older Android versions still support the normal app editor but do not expose this shortcut.
4. Enter a title and optional description. **Device only** is the default and works without sign-in or a token-store read. Tap **Save task**, then open the main app's device task list to check it.
5. To capture for an account, first sign in through the main app. In capture, tap **Choose current account**, review the displayed email and API origin, and Save. This writes to that account's local sync queue without an HTTP request. Open the normal synced workspace and complete its usual verification/sync flow to upload it. The separate online workspace will only show it after synchronization.
6. **Cancel** or Back discards a draft that has not been submitted. The screen closes after a confirmed save. Draft text is not copied into an intent or saved-instance Bundle; leaving/recreating the activity can discard it. A Save already submitted may finish even if Android closes the screen; check the workspace before starting another capture.

Native phone behavior is not yet accepted. No phone/emulator installation, permission change or launcher interaction was performed by the assistant.

## Phase 15B: share text into a draft

From a notes app or browser, select text or a link, choose **Share**, then select Todo App / Quick capture (the name shown depends on the Android launcher and Sharesheet). The target advertises only single `ACTION_SEND` with `text/plain`, available on the app's existing API 21+ minimum. This surface does not require the API 25 launcher shortcut feature.

Review **Review shared text**, edit the fields if needed, choose the destination and tap **Save task**. Device only is always the default, including when signed in. Account selection and subsequent offline queue/sync behavior are identical to launcher capture. Sharing itself never saves or uploads a task; Cancel/Back discards an unsubmitted draft.

A nonblank subject becomes the title and the entire shared body becomes the description. Without a subject, the first nonblank line becomes the title and the remaining lines become the description. CRLF/CR newlines become LF; surrounding whitespace is trimmed using the normal domain rules. Titles must fit 200 characters and descriptions 4000. Overlong titles/descriptions, multiline subjects, empty text, NUL/unsupported control characters and malformed extras open an empty editable form with a generic notice. No partial/truncated import is saved. Raw input is bounded to 8192 UTF-16 characters for body and 512 for subject before copying; styled CharSequence input is copied as plain characters without retaining spans.

Only the two text extras are read. Image/file streams, ClipData, HTML extras, URI permissions and external task/account/origin identifiers are ignored. HTTP/content/file URL text stays literal text; the app does not fetch it, interpret HTML or open attachments. Other actions/MIME types close immediately even when explicitly addressed. The launcher action still ignores all extras and opens a blank form.

The Activity drops foreign extras from its own intent after input extraction. Drafts are not copied into saved-instance Bundles or SQLite until explicit Save. Android/sending apps may retain their own copy of the original shared intent; this app does not control those copies. Re-creation with saved state opens an empty form with a recovery notice instead of re-importing original text. Rotation covered by the existing Activity configuration keeps the current form; process death/other configuration changes can discard unsaved edits. An already submitted Save may still commit after closure, so check the workspace before another capture. Each separate deliberate share opens a fresh capture; there is no content-based deduplication between separate shares.

Implementation follows [Android's official receiving-data guidance](https://developer.android.com/develop/ui/compose/sharing/receive), including a narrow MIME filter and a review/edit step. It adds no packages, permissions, database schemas, server endpoints or sync protocol changes.

## Phase 15C: home-screen Add task widget

After building and installing the current APK, long-press an empty area of your Android home screen, open **Widgets**, find **Todo App quick capture**, and drag it onto the home screen. Exact picker labels/steps depend on the launcher. The widget works with the app's API 21+ minimum and a launcher that supports app widgets; it does not require the API 25 app-shortcut feature. Newer launchers receive a two-column/one-row size hint; older launchers calculate their own size from minimum dimensions. It can resize horizontally and vertically.

Tap **+ Add task** to open a new blank capture form. Enter a task, keep Device only or explicitly choose the current account, then Save. Cancel creates no task. This is an entry widget, not an inline editor, task list, account selector or sync control. It uses the same domain validation, pinned account authorization, offline queue and schema-7 receipts as the other capture surfaces. There is no automatic Save or upload.

The widget contains only a generic button/accessible description; no task title, count, email, origin, draft or saved session is passed to the launcher. A nonexported AppWidgetProvider publishes static RemoteViews and a component/action-bound Activity PendingIntent. It uses Immutable on API 23+; API 21/22 have no immutable flag, but the fixed capture action ignores all incoming extras and defaults to Device only. No widget ID or account identity selects a destination. A direct Activity launch with NewTask/MultipleTask keeps the existing main editor/capture task separate. Each deliberate tap can open a separate form with its own capture ID; check for earlier saves before creating another.

`updatePeriodMillis=0` disables widget periodic refresh. Widget update/restore only rebuilds the static view and click action; it resolves no app services, reads no databases/credentials, makes no HTTP/location/permission request, starts no geofence run and schedules no alarm/job. Framework process creation still initializes the Android application; the widget code does not create a MAUI window or attach its runtimes. Instances have no app-owned configuration or state to delete. Removing/re-adding a widget does not remove tasks, sign out an account or alter existing reminder choices. No programmatic pin/configuration flow is included; use the launcher's normal picker.

On saved-state capture recreation, the existing empty-form recovery notice applies. A widget's static preview is generic too. Native host behavior, resizing, keyboard/TalkBack, task-stack preservation and background launch restrictions require real-device acceptance. On modern Android, the visible widget host must supply the appropriate PendingIntent launch privileges; this provider does not grant broad creator-side background launch privileges. Check cold taps with the selected launcher, and inspect ActivityTaskManager/BAL logs if Android blocks them; a debug build cannot establish host compatibility. See [Android activity security guidance](https://developer.android.com/guide/components/activities/secure-bal). Follow [Android's widget provider documentation](https://developer.android.com/develop/ui/views/appwidgets) and [update-frequency guidance](https://developer.android.com/develop/ui/views/appwidgets/advanced); builds do not prove launcher behavior.

## Design and data flow

`MainActivity` declares a static `android.app.shortcuts` resource. Its generic Add task entry explicitly starts `QuickCaptureActivity` with one fixed action. The launcher action ignores every intent extra. Phase 15B also accepts bounded plain-text shares as editable prefills; external account/ID/origin/token values never select a destination. Other actions/types close immediately. The entry opens a compact native form without creating the normal MAUI window, attaching its runtimes or navigating away from its editor. Its separate empty task affinity keeps launcher shortcut task flags away from the main app task, and it is excluded from Recents.

The native view delegates to the portable `QuickCaptureViewModel` and `QuickCaptureService`. Domain `TaskItem` validation trims title/description and enforces 200/4000-character limits. Captures are pending, normal priority, without due date, category, tags, parent, prerequisites, quadrant assignment or recurrence. Advanced fields remain available in the normal editor. No new permissions, packages or server endpoint are required. Capture does not start/rearm a geofence run or request a position/notification permission; existing background reminder policy still applies.

Account selection explicitly restores only an unexpired saved session matching the configured HTTPS origin. Offline capture permits an unverified restored session because it writes only that user's local partition; it does not grant server access. The selected origin/user/session generation is pinned. The service checks it and expiry inside the SQLite operation and again before commit. Sign-out, expiry or endpoint/account replacement rejects the save instead of silently targeting another workspace. Device saves do not restore credentials. Native UI displays a generic recovery message; drafts/errors are not logged.

## Retry and migration behavior

Each capture screen creates one random capture/task ID. The first valid Save freezes both normalized fields and destination. While saving, controls are disabled. Storage failure keeps the same ID and draft for **Retry same save**, with destination and text locked; close and check the workspace before starting another capture. Validation errors remain editable. A confirmed save cannot be repeated from that view model.

Device task schema **7** adds `QuickCaptureReceipts(Id,Fingerprint)`. The task and its SHA-256 normalized-payload fingerprint receipt commit in one transaction. Account sync schema **7** adds `CaptureReceipts` to each replica partition; the new task, immutable outgoing operation and receipt commit together. Retries with the same payload confirm the receipt without overwriting later edits, replacing an outgoing operation or resurrecting a deleted task. Reusing an ID with different fields fails. Receipts survive task deletion; they contain IDs/hashes, not a second plaintext draft. Existing task/cache files upgrade transactionally; newer schemas are rejected without reset. Older app versions reject schema 7, so do not downgrade against these files.

Receipts are retained up to 10,000 per device database or account partition. At capacity, new quick captures are refused and the normal editor remains available. There is no automatic receipt pruning, separate draft database, cross-workspace move or automatic sync. Server migrations remain eight and the sync wire protocol remains **6**. Normal task text retains the existing SQLite/backup protection limits; capture does not add database encryption or change Android's existing backup configuration.

## Reproducible package checks (Phase 16A)

Build-Android.ps1 now automatically runs Test-AndroidPackage.ps1 after debug signing. It checks the actual APK's capture/widget/share resources, native component/permission boundaries, signatures and embedded assemblies and writes ignored .tools/android-audit/debug-report.json. Its success means the development artifact matches the current baseline, not that launcher/phone behavior or release readiness passed. See [ANDROID_RELEASE_READINESS.md](ANDROID_RELEASE_READINESS.md) for commands, failure cases and the open acceptance/recovery matrix.

## Verification performed

Phase 15C final regression: all 708 existing tests passed with no failures/skips (649 portable, 59 PostgreSQL). The 37 targeted capture cases include 19 new share cases and the earlier 18 capture cases. The Android standalone debug APK and Windows solution compile with zero warnings/errors. APK inspection confirms v1/v2/v3 signatures, embedded assemblies, explicit capture activity/task attributes, its ACTION_SEND/DEFAULT/text/plain filter, preserved launcher metadata and versioned shortcut resources with labels/icon/target. Widget inspection also confirms a nonexported provider with APPWIDGET_UPDATE filter/metadata, packaged button/accessible description, 64dp minimum height, home-screen resizing, zero periodic updates and the generated versioned preview/two-by-one cell hints. apksigner emits AndroidX META-INF/JAR coverage warnings; release packaging remains a separate gate. No native phone/launcher outcome is inferred from these checks.

## Acceptance still required

- Install and use a compatible launcher on API 25+; check cold/warm entry, optional pinning, double-taps and preservation of the main editor/navigation stack.
- Save/cancel offline device drafts, whitespace/length boundaries, keyboard scrolling, rotation/background/process death and interrupted saves. Verify a committed save can be found after the screen disappears.
- Choose a restored account offline, confirm its email/origin, queue, reopen the synced workspace, verify and upload once. Test expired sessions, sign-out/API changes and multiple accounts without retargeting.
- Exercise TalkBack labels/live errors, large fonts, small screens, dark mode and keyboard-only/switch navigation on actual devices. The form currently uses the Android light dialog theme.
- Check that launcher activation ignores extras; share activation imports only bounded text/subject and never auto-saves. Try browsers/notes apps, selected text, links, styled text, missing/malformed extras, oversized bodies/subjects, attachments and unsupported types. Confirm Cancel creates no task and account selection remains explicit.
- Verify two shares create separate review forms without overwriting a submitted draft or disturbing the main editor. Recreate/background/kill during review and saving; original text must not auto-save or silently replay. Check that a completed task can be found before starting another capture.
- Review launcher/Sharesheet OEM behavior, backup/restore and release signing separately.
- Add, resize, remove/re-add and restore multiple widgets on API 21/22 and modern launchers where available. Check minimum tap area/large fonts/TalkBack, light/dark display and preview. Cold/warm taps must open blank review with Device only; no task/account data should appear on the home screen. Confirm Save/Cancel, explicit account selection/offline queue and existing editor/draft preservation.
- Reboot/update/force-stop/reopen with widgets present; confirm static widget rebinding does not sign in, sync, prompt for location/notification permissions or restart reminder runs. Removing widgets must preserve tasks and reminder choices.
- Complete the earlier Windows/Android geofence acceptance, Apple support and Google/provider gates independently. Compilation and portable tests do not establish these runtime outcomes.

The static entry follows [Android's official shortcut creation documentation](https://developer.android.com/develop/ui/compose/system/shortcuts/creating-shortcuts). Native Android types remain in Platforms/Android; the portable service, view model and real SQLite behavior are tested without an emulator.
